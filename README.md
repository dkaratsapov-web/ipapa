# IPapa Price Bot

Telegram-бот с актуальными ценами и наличием в магазине **айпапа.рф**. Бот также присылает уведомления об изменениях цен.

Данные берутся из публичного WooCommerce Store API сайта
(`/wp-json/wc/store/v1`), HTML не парсится.

## Возможности

**Пользователям**
- `/start` открывает меню: «Каталог», «Поиск», «Мои подписки».
- Каталог: категории, затем подкатегории, затем товары с минимальной ценой (по 10 на страницу), затем карточка товара.
- Поиск: достаточно написать текст, например `iphone 17 pro 256`. Бот ищет по всем словам, без учёта регистра, в названии товара и в описании варианта.
- Карточка товара: фото, ссылка на сайт, варианты с ценой и наличием (✅/❌), отсортированные по цене. Старая цена показывается зачёркнутой, указано время обновления.
- «🔔 Следить за ценой»: подписка на весь товар или на отдельный вариант. Бот сообщает об изменении цены или о появлении товара в наличии.
- «Мои подписки» (или `/subs`): список подписок с отпиской.

**Администраторам** (ID из `ADMIN_IDS`)
- `/sync`: синхронизация вручную с отчётом о результате.
- `/changes [N]`: изменения цен за N часов (по умолчанию 24).
- `/stats`: пользователи, подписки, последняя синхронизация.
- `/digest`: ежедневная сводка прямо сейчас. По расписанию сводка приходит в `DIGEST_TIME`.
- Если синхронизация по расписанию не удалась, администраторы получают уведомление.

## Как устроено

```
main.py               запуск: бот, планировщик (APScheduler), логирование
config.py             чтение .env
bot/                  хендлеры (handlers/user.py, handlers/admin.py), клавиатуры, тексты
services/api_client   httpx-клиент: 1 запрос/с, UA IPapaPriceBot/1.0, таймаут 30 с, 3 ретрая
services/sync         синхронизация, поиск изменений, защита от сбоев
services/notifier     рассылка (пауза 50 мс, RetryAfter, блокировка -> пользователь неактивен)
services/reports      /changes и ежедневная сводка
db/                   схема SQLite и запросы (aiosqlite)
scripts/              разовая синхронизация и снятие фикстур с сайта
tests/                pytest + JSON-фикстуры
```

**Синхронизация** запускается при старте, а затем каждые `SYNC_INTERVAL_MIN` минут:
1. Постранично загружаются все товары, затем все варианты (`type=variation`), затем категории.
2. Если хотя бы один запрос завершился ошибкой (после 3 попыток) или товаров либо вариантов пришло меньше 50 % от прошлой успешной синхронизации, результат **не применяется**. Ошибка пишется в `sync_log`, администраторы получают уведомление.
3. Цена и наличие каждого варианта или простого товара сравниваются с базой. Изменения записываются в `price_history`, и эта же таблица служит очередью уведомлений.
4. Все изменения применяются одной транзакцией. Товары, которых нет в ответе, помечаются `is_active = 0` и не удаляются.
5. Первая синхронизация на пустой базе уведомлений не рассылает.

Цены хранятся целыми числами в копейках. Цена `0` означает «Цена по запросу»: в уведомлениях и отчётах об изменениях цен она не учитывается.

## Запуск через Docker (рекомендуется)

```bash
cp .env.example .env      # заполнить BOT_TOKEN и ADMIN_IDS
docker compose up -d
docker compose logs -f
```

База и логи лежат в volume `ipapa-data` (`/app/data` внутри контейнера).

## Запуск в GitHub Actions (без сервера)

Workflow `.github/workflows/bot.yml` запускает бота на раннере GitHub.
- Каждый запуск работает около 5 ч 40 мин (`RUN_DURATION_MIN=340`), затем бот штатно завершается.
- Cron каждый час ставит следующий запуск в очередь, а `concurrency` не даёт двум копиям бота работать одновременно. Поэтому новый запуск стартует сразу после окончания предыдущего, перерыв около минуты.
- База SQLite переносится между запусками через `actions/cache`.

Настройка:
1. Settings → Secrets and variables → Actions → **Secrets**: добавить `BOT_TOKEN` и `ADMIN_IDS`.
2. Необязательно, во вкладке **Variables**: `SYNC_INTERVAL_MIN`, `DIGEST_TIME`.
3. Actions → **bot** → **Run workflow**. Дальше запуски пойдут по расписанию.

Ограничения:
- Это временное решение. Пока идёт перезапуск (~1–2 мин), бот не отвечает, а сообщения, пришедшие за это время, обработаются после старта.
- GitHub отключает расписание, если в публичном репозитории 60 дней не было активности.
- Кэш хранится до 7 дней без обращений. Если бот простоит неделю, база начнётся заново: подписки пропадут.
- Раннеры GitHub находятся за рубежом. Если сайт магазина закрыт для зарубежных IP, синхронизация будет падать, и админ получит уведомление.
- Репозиторий публичный, поэтому логи Actions видны всем. Токен GitHub в логах маскирует, но ID администраторов тоже лучше хранить в secrets.

## Мини-апп (Telegram Web App)

Приложение-витрина на React (`webapp/`: Vite, TypeScript, Framer Motion) в стиле айпапа.рф, с логотипом и анимированной заставкой. В нём есть:
- каталог, поиск (понимает «айфон 17 про»), карточка товара с выбором цвета и памяти и характеристиками;
- избранное, корзина и сравнение до 4 устройств. Хранятся на устройстве и в облаке Telegram, поэтому общие для телефона и компьютера;
- оформление заказа из корзины через менеджера;
- трейд-ин: калькулятор по прайсу сайта (страница /trade-in/) и заявка на расчёт;
- сервисный центр: запись на диагностику, адреса и телефон;
- подписки на цену.

Заявки (заказ, ремонт, трейд-ин) приходят в бота. Бот сохраняет их в таблицу `leads`, пересылает в `LEADS_CHAT_ID` (или администраторам, если он не задан) и просит у клиента телефон кнопкой. Администраторы смотрят последние заявки командой `/leads`.

Характеристики устройств берутся из справочника `reference/specs.yaml`: раздел → модель → «подпись: значение», по строке на поле. Модель находится по названию товара без памяти, цвета, года и SIM; другие написания задаются полем «Другие названия». Модели из каталога, по которым данных пока нет, перечислены в конце разделов как заготовки `{}` — заполните их, и характеристики появятся в карточках после ближайшего обновления каталога. «Дата выхода» используется для сортировки «Сначала новые».

Фото для товаров без фотографий (в основном Б/У) подбираются автоматически: сначала фото той же модели из каталога, затем из статьи о модели в английской Википедии.

Как это работает:
- После каждой успешной синхронизации бот выгружает каталог в `catalog.json` (`EXPORT_PATH`) и публикует его командой `EXPORT_CMD`. В GitHub Actions каталог уходит в ветку `webapp-data`.
- Мини-апп читает `catalog.json` с `raw.githubusercontent.com`. Источник можно поменять через `VITE_DATA_URL` или параметр `?data=`.
- Своего сервера у приложения нет, поэтому подписки передаются через бота. При запуске с кнопки клавиатуры используется `sendData`, при запуске из меню или из карточки — deep link `/start s<ID>` или `/start u<ID>`. Текущие подписки бот передаёт приложению в адресе (`?subs=`).

Публикация на GitHub Pages:
1. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. Workflow `miniapp` соберёт приложение при изменениях в `webapp/`. Его можно запустить и вручную.
3. Адрес по умолчанию: `https://dkaratsapov-web.github.io/ipapa/`. Другой адрес задаётся переменной `MINIAPP_URL` в Settings → Variables.

Разработка:
```bash
cd webapp && npm install
npm run dev            # затем открыть http://localhost:5173/?demo=1 (демо-каталог)
```

## Запуск через systemd

```bash
sudo useradd --system --home /opt/ipapa ipapa
sudo git clone <repo> /opt/ipapa && cd /opt/ipapa
sudo python3.11 -m venv .venv && sudo .venv/bin/pip install -r requirements.txt
sudo cp .env.example .env && sudo nano .env
sudo chown -R ipapa /opt/ipapa
sudo cp deploy/ipapa-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now ipapa-bot
journalctl -u ipapa-bot -f
```

### Фикстуры тестов

Файлы `tests/fixtures/*.json` имеют формат ответов Store API (`items` содержит тело ответа).
Чтобы заменить их реальными ответами сайта:

```bash
python scripts/fetch_fixtures.py --limit 20
pytest
```

Скрипт также выводит `X-WP-Total` и `X-WP-TotalPages` по товарам и вариантам.
После замены фикстур тесты, которые завязаны на конкретные ID и цены (`tests/test_sync.py`, `tests/test_bot_smoke.py`), нужно будет подстроить под новые данные.

## Проверка критериев приёмки

- **Число записей.** `/sync` показывает, сколько товаров и вариантов загружено, рядом со значением `X-WP-Total`.
- **Изменение цены.** Поменяйте цену в базе, выполните `/sync`: подписчик получит уведомление, а изменение появится в `/changes`.
  ```bash
  sqlite3 data/ipapa.db "UPDATE products SET price = price + 500000 WHERE id = <id варианта>"
  ```
- **Сбой API.** Укажите в `SITE_API_URL` неверный адрес и выполните `/sync`: база останется прежней, придёт сообщение об ошибке.
